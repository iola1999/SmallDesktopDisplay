# Roadmap

这个文档记录远程渲染桌面小屏的后续方向。这里保持轻量，只放产品和架构层面的路线；具体协议、性能和实现细节放在其他文档里。

## 近期

- 把当前中文桌面时钟打磨成稳定日常界面：更清晰的状态提示、更稳的错误降级、更少干扰的同步反馈。
- Web 控制台基础已经完成：React/Vite 工作台、版本化配置、首页预设、草稿预览、ETag 冲突处理、浏览器验收和 launchd 发布均已完成。
- 按[Web 控制台与配置模型提案](../.agents/notes/proposed/architecture/2026-08-23-Web控制台与配置模型.md)继续实现页面注册表、状态页面列表和数据源配置。
- 按[桌面内容页面与同步歌词提案](../.agents/notes/proposed/feature/2026-08-23-桌面内容页面与同步歌词.md)验证系统 Now Playing、本地 LRC 和网络歌词来源。
- 继续完善屏幕内 Settings 的设备控制项和只读诊断项，优先处理部署、排障和日常使用需要的能力。
- 继续强化配置链路：新设备 ID 已统一使用 ASCII 安全字符规则，后续检查 AP fallback、局域网配网页、远端服务地址修改和远端不可用时的本地提示。
- 保持固件职责足够小：WiFi、配网页、按键、状态上报、命令执行和 TFT 输出。
- 继续用本地 PNG 预览工具验证 UI 改动，再上设备做显示效果和时序确认。

## 远端渲染服务

- 已使用 React 与 Vite 构建 Web 控制台，TanStack Query 管理服务状态和配置缓存，Motion 处理克制的界面过渡；构建产物继续由 Node.js 提供。
- 首页采用布局预设和受约束槽位，允许关闭天气，选择当前值、今日高低温、小时预报和未来日预报等字段。
- 建立页面注册表，统一处理启停、顺序、默认页、自动出现、停留时间和回退。
- 数据源按服务级配置管理，页面只引用播放器、歌词、天气、日历和本机状态的标准视图模型。
- 继续打磨 Node.js 自定义 React renderer、Yoga 布局和 Skia 光栅化能力，减少页面开发时大量手写坐标。
- 动画继续优先控制 payload，大面积变化尽量拆成较小 dirty region。
- 为常开部署补齐更清楚的运行检查，例如服务健康、设备状态新鲜度、最近帧信息和预览输出。

## 设备固件

- 保持串口自动探测与 WiFi HTTP 回退，分别记录帧大小、传输时间和 TFT 写入时间。
- 避免 ESP8266 上的全屏帧缓冲，继续用流式读取和小批量 TFT 输出控制 RAM 压力。
- 保留并扩展客户端状态上报，把有用的设备侧诊断指标同步给远端 UI。
- 优先增加小而明确的命令类型，例如重启、旋转、诊断采集或配置刷新。
- 保持 `src/AppConfig.h` 为编译期默认值入口，运行时可变配置继续通过设备配网页持久化。

## 部署

- Mac 继续通过 launchd 运行原生 Node.js 进程，保留 Linux 主机、NAS 和小主机的 Docker 部署方式。
- 远端渲染服务始终通过 URL 配置，不假设特定主机、固定 IP 或具体网络环境。
- 为长期运行补齐基础可观测性：健康检查、日志轮转、设备最近在线时间和简明故障提示。
