本阶段不加入状态页面列表、天气位置与单位、音乐和歌词数据源。首页设置只使用渲染器已经拥有的时钟、日期、农历和天气内容。

配置保存到 `STATE_DIR/remote-render-config.json`。每次修改先写权限为 `0600` 的临时文件，再用原子替换发布；落盘成功后才更新内存版本。第一次迁移 `device-prefs.json` 时先保留 `device-prefs.json.migrated.bak`，再发布新版配置。损坏文件、未知 `schemaVersion` 或保存失败会把配置存储置为只读，并在控制台显示原因。

配置写入要求带双引号的全局修订 ETag。服务端收到过期 `If-Match` 时返回 `409` 和当前修订号。控制台读取最新版后按字段合并本地修改，并继续自动同步。主题、字体和首页设置使用配置队列；亮度使用独立命令队列并保存在设备 EEPROM。

TanStack Query 在写入开始时取消同设备的配置请求，响应按修订号更新缓存。保存请求返回时，reducer 按本次发送值合并期间产生的新操作；较旧的 GET 结果不会覆盖当前配置。发布和回退串行执行，冲突恢复按发起操作的设备 ID 更新查询。开关整行可点，实时预览的每秒后台刷新保持已显示画面的亮度不变。

发布会创建配置内容不变的稳定修订，并把当时的设备配置写入 `STATE_DIR/remote-render-config-history/`。历史最多保留最近 100 个发布版本。回退恢复指定设备并生成当前配置修订，发布版本集合保持原样。启动时清理旧格式中未发布的快照，详细规则见[控制台实时同步与版本历史](../architecture/2026-08-23-控制台实时同步与版本历史.md)。

设备配网页对新设备 ID 使用 `1-23` 位 ASCII 字母、数字、点、下划线或连字符。Node.js 服务继续接受非空历史 ID，旧配置和串口设备可以继续读取。配置映射使用无原型对象，`__proto__` 等历史 ID 不会改变对象原型。

串口上行 JSON 现在会拒绝 `null`、数组和其他非对象值。状态消息对亮度、运行时间及可选内存、碎片率、RSSI 字段做范围校验；控制台区分未上报字段和真实零值。

### Web 控制台 Deviations

初始提案计划先拆分无构建静态资源。用户确认使用 React、TanStack Query 和 Motion 后，控制台改为 Vite 独立构建，产物继续由同一个 Node.js 服务提供。状态页面列表等第一个真实状态页出现后再实现，让设备内部设置流程与内容页面保持清晰。

亮度最初被归入只读设备状态。实际控制台允许修改亮度，仍沿用设备命令和 EEPROM 存储。自动同步阶段将亮度拆为独立队列，配置错误和设备命令错误可以分别重试。

当前 launchd plist 的 `SERIAL_PORT` 仍指向 `/dev/cu.wchusbserial21120`，当前存在的设备节点是 `/dev/cu.wchusbserial3120`。`desk-01` 通过 WiFi HTTP 回退与服务通信。本轮发布保留原有串口运维配置，设备节点更新留给单独的运维变更。
