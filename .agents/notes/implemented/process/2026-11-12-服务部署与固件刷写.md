## 决策

2026-11-12 将该提交构建为服务和 ESP8266 固件，完成刷写并恢复 launchd。部署继续使用本机原生 Node.js 进程。

### 部署过程

- 备份 `com.sdd.remote-render.plist`、`remote-render/data`、此次固件与服务构建产物。备份目录为 `~/Library/Application Support/SmallDesktopDisplay/backups/2026-11-12-d08b46c-fgrbuhn7`，目录权限为 `0700`。
- `npm run build` 成功后停止 `com.sdd.remote-render`，释放串口。
- 将 launchd 的 `SERIAL_PORT` 从 `/dev/cu.wchusbserial3110` 更新为检测到的 `/dev/cu.wchusbserial3120`。设备 USB VID:PID 为 `1A86:7523`，串口通信仍使用 921600 波特率。
- 执行 `pio run -e esp12e -t upload --upload-port /dev/cu.wchusbserial3120`。工具识别 ESP8266EX，写入 511,680 B 固件，哈希校验成功，并通过 RTS 复位。
- 使用 `launchctl bootstrap` 恢复服务，设备自动建立串口连接。部署脚本通过 `finally` 保证上传流程退出后尝试恢复 launchd。

普通上传只写入固件区域。本次存储格式保持版本 3，EEPROM 所在 Flash 偏移为 `0x3FB000`，与固件写入范围分离。

## 曾考虑的替代方案

- 只重启服务：无法部署固件中的配网、双击窗口和坏帧恢复修复。
- 继续使用错误串口路径：会持续报错并依赖 WiFi 回退，因此同步修正为检测到的节点。
- 清除整个 Flash：存储格式未变，普通上传与 EEPROM 地址范围分离，保留原配置即可。
- 部署时更换页面或外观：现有持久化配置有效，直接保留。
