# 决策记录: 桌面内容页面与同步歌词

状态: proposed

## 问题

设备目前主要显示时钟、日期、农历和天气，设置页提供亮度、字体与诊断。Mac 上常驻的 Node.js 进程可以读取本机状态，也可以通过串口低延迟推送局部画面。现有能力给内容扩展留下了很大空间，仓库还缺少一份可以筛选、排序和逐步验证的页面清单。

240x240 屏幕面积有限。每个页面都需要回答一个清楚的问题，并说明数据来源、刷新频率、失败状态、隐私和串口开销。未经筛选地堆叠小组件会降低远距离阅读效果。

## 提案

### 内容原则

- 首屏信息在一到两秒内可以读完，字号优先于信息数量。
- 高频变化采用局部刷新；封面、照片等大图只在内容变化时更新。
- 自动出现的页面只处理有时效的事件，例如切歌、会议临近、计时结束和构建失败。
- 网络数据失败时保留最后一次可用值或安静隐藏，错误详情进入 Web 控制台。
- 默认只保存配置和必要缓存。播放记录、日程正文、通知正文等内容需要单独设计保存期限。
- 每个内容源都提供关闭入口，页面停用后保留参数，重新开启时可以恢复。

### 第一组：正在播放与同步歌词

这组最适合先做。Mac 已有稳定的宿主进程，曲目和歌词变化通常只影响屏幕的一小块区域。

正在播放页可以提供以下布局预设：

- `lyrics_focus`：当前歌词居中，上一句和下一句降低对比度，底部显示歌名与进度。
- `cover_lyrics`：左上或满幅封面取色，歌词放在高对比区域，背景颜色随专辑变化。
- `now_playing`：封面、歌名、歌手、播放状态和进度，适合没有同步歌词的曲目。
- `text_only`：只显示歌词和曲名，关闭封面与视觉效果，适合远距离阅读和夜间使用。
- `visualizer`：小面积频谱或波形配合曲目信息，刷新范围与帧率受到严格限制。

播放状态采集按适配器处理：

1. 系统 Now Playing：覆盖 Music、Spotify、浏览器和多数使用系统媒体中心的播放器。
2. Apple Music：通过 Music.app 自动化接口补充曲目和播放控制。
3. Spotify：需要更可靠的跨设备状态时启用 Web API 适配器。

系统适配器可以调用 [`nowplaying-cli`](https://github.com/kirtan-shah/nowplaying-cli)，它能返回标题、歌手、专辑、时长、进度和封面。该工具依赖 macOS 私有 MediaRemote 框架，系统升级后需要回归验证。

歌词来源使用有序列表，首版建议：

1. 本地同名 `.lrc` 文件和用户指定歌词目录。
2. 已命中的本地缓存。
3. [LRCLIB](https://github.com/tranxuanthang/lrclib) 的同步歌词接口。
4. 播放器提供的纯文本歌词或用户手工粘贴内容。

匹配键至少包含歌名、歌手、专辑和时长。结果需要记录来源与匹配置信度，允许用户在控制台修正错误匹配。双语歌词、时间偏移、逐字歌词可以在基础逐行同步稳定后再加入。纯音乐、广告、播客和缺词曲目显示明确的简短状态。

切歌时更新封面和完整页面；播放进度与当前歌词只更新相关区域。暂停后保留页面的时间由用户配置，停止播放后回到上一个页面。

### 第二组：有时效的桌面状态

| 页面 | 适合显示的内容 | 建议来源 | 刷新与触发 |
| --- | --- | --- | --- |
| 下一场日程 | 标题、开始时间、剩余时间、会议方式 | macOS Calendar、ICS | 每分钟；开始前自动出现 |
| 专注计时 | 当前阶段、剩余时间、今日完成次数 | 控制台、本地计时器 | 每秒局部刷新；开始和结束触发 |
| 构建与测试 | 仓库、分支、任务、结果、耗时 | 本地脚本、GitHub Actions | 状态变化时更新；失败优先 |
| Git 工作区 | 当前仓库、分支、改动数量、最近提交 | 本机 `git` | 进入页面时或低频轮询 |
| Mac 状态 | CPU、内存、磁盘、网络、温度或电量 | macOS 本地命令 | 5 至 30 秒；异常时触发 |
| 下载与任务 | 当前传输、剩余时间、后台任务 | 应用适配器 | 状态变化时更新 |
| 家庭状态 | 温湿度、空气质量、门窗、能耗 | Home Assistant、MQTT | 事件与低频轮询结合 |
| 出行 | 下一班公交、通勤时间、航班状态 | 公共交通或航班服务 | 临近出发时自动出现 |

会议标题、仓库路径、下载文件名和家庭状态都可能包含敏感信息。控制台需要逐项选择显示字段，日志使用摘要或状态码。

### 第三组：低频与环境内容

- 天气扩展：当前值、体感温度、今日高低温、降水、空气质量、日出日落和未来一到三天。用户可以只保留需要的字段。
- 日历内容：农历、节气、纪念日、生日倒数、今年进度和习惯连续天数。
- 阅读内容：RSS 标题、稍后读、每日短文、诗词、单词和“历史上的今天”。
- 视觉内容：照片回忆、专辑封面、生成式像素图案、文字时钟、月相、星图和 NASA 天文图片。
- 兴趣页面：比赛比分、游戏状态、直播状态、包裹进度、航班雷达、ISS 过境和深空网络状态。
- 轻交互：投票、随机选择器、呼吸节奏、番茄钟、桌面角色和简单回合游戏。

开源信息屏已有大量可复用的内容分类。[Tidbyt Community](https://github.com/tidbyt/community) 把时钟、交通、空气质量、日历、媒体和小游戏做成独立应用；[Pixlet](https://github.com/tidbyt/pixlet) 让应用声明配置并输出受限屏幕画面；[TRMNL plugins](https://github.com/usetrmnl/plugins) 覆盖日历、GitHub、RSS、包裹、天气、Statuspage、Home Assistant、Last.fm 和目标追踪。当前项目可以吸收它们的页面注册和配置思路，渲染继续沿用 React、Yoga 与 Skia。

同步歌词桌面屏的公开案例还反映了几项实际需求：亮度要能压得足够低；用户希望在纯歌词、封面和抽象视觉之间选择；单一音乐用途容易受限，天气和日历等页面能提高日常使用频率。参考：[Reddit 案例与讨论](https://www.reddit.com/r/Design/comments/1sb34x3/built_a_small_desk_display_for_music_with_synced/)。

### 页面调度

每台设备维护一个有序页面列表，支持以下行为：

- 手动轮换：短按按列表顺序切换启用页面。
- 自动出现：数据源产生事件时临时显示页面，规则包含优先级、最短展示时间和超时。
- 临时固定：用户可以把当前页固定一段时间，期间屏蔽普通自动出现事件。
- 安静时段：降低亮度，限制动画，并关闭低优先级自动页面。
- 回退页面：事件页结束或数据源不可用时，返回先前页面或指定首页。

系统同一时刻只显示一个自动页面。高优先级事件可以替换低优先级事件；相同优先级按发生时间排队。具体字段由[Web 控制台与配置模型](../architecture/2026-08-23-Web控制台与配置模型.md)提案定义。

### 串口与渲染约束

- 歌词行、计时器和状态文本适合局部矩形更新。
- 封面在切歌时传输一次，服务端缓存缩放后的 240x240 素材。
- 频谱和波形限制在局部区域，首版从 5 FPS 开始实机测量，再决定上限。
- 照片、全屏渐变和大面积动画需要测量帧大小、串口占用和 TFT 写入时间。
- 数据源刷新频率与画面刷新频率分开，天气拉取一次可以供多次渲染使用。

### 建议实施顺序

1. 建立页面注册表、启用列表和手动排序，不接入新数据源。
2. 接入系统 Now Playing，完成 `now_playing` 与 `text_only` 两种页面。
3. 加入本地 LRC、缓存和 LRCLIB，完成逐行同步、偏移校正和缺词状态。
4. 加入自动出现、暂停保留、安静时段和临时固定。
5. 从日程、专注计时、构建状态中选择一个本地来源，验证页面扩展方式。
6. 根据串口测量结果评估封面取色、频谱和照片页面。

## 曾考虑的替代方案

- 把所有内容放进首页：240x240 下会压缩字号，也会让天气、歌词和临时事件互相争夺空间。
- 每个新页面直接增加独立配置字段：实现初期较快，页面增多后会重复处理启停、排序、自动出现和降级。
- 只做音乐屏：公开案例中的反馈显示，歌词需求因人而异；可选的日程、天气和状态页能覆盖更多日常场景。
- 首版采用高帧率全屏音乐可视化：串口带宽、TFT 刷新和长期视觉干扰都需要先测量，局部低帧率方案更适合第一轮验证。

## 验收标准

- 明确首批要实现的页面、数据源和实施顺序，并由维护者确认。
- 每个首批页面记录显示字段、空状态、刷新频率、手动交互和自动出现规则。
- 播放器适配器在 Music、Spotify 和浏览器播放场景中至少覆盖两个来源，并记录缺失权限与系统版本行为。
- 歌词链路支持本地 LRC、缓存和一个网络来源；错误匹配可以在控制台修正。
- 页面启停、排序、回退和自动出现行为有状态测试。
- 预览图覆盖最长文本、无封面、纯音乐、歌词缺失和双语文本。
- 实机记录切歌、歌词更新和局部动画的帧大小、传输时间与 TFT 写入时间。

## 风险

- 歌词内容受版权和服务条款约束。实现前需要确认所选来源的使用条件、缓存范围和展示边界。
- LRCLIB 或其他网络来源会收到曲名、歌手、专辑、时长和请求 IP。网络查词应由用户主动启用，并在控制台显示当前来源。
- MediaRemote 属于 macOS 私有框架，系统升级可能导致适配器失效。Music.app 和 Spotify 适配器需要保留独立降级路径。
- 日程、播放状态、仓库名和家庭传感器属于私人数据。默认不保存历史，日志过滤正文和本地路径。
- 高刷新率页面会增加串口和 TFT 负载，也会产生持续视觉干扰。每个动画页面需要帧率上限和安静时段行为。
- 自动出现规则过多会频繁切页。首版只开放少量事件类型，并在控制台显示最近一次触发原因。
