# 决策记录: Web 控制台与配置模型

状态: proposed

## 问题

提案形成时，远端渲染服务已经有 Web 控制台，入口是 `/` 和 `/console`。旧控制台支持设备选择、PNG 预览、模拟按键、主题、字体、亮度、天气缓存与设备状态。页面由 `remote-render/src/console.ts` 中的单个 HTML 字符串提供，持久化只保存每台设备的主题和字体；亮度由设备 EEPROM 保存。

音乐软件、歌词来源、状态页面列表和首页布局会让配置规模明显增加。现有偏好结构无法表达服务级数据源、设备级页面实例、布局草稿、敏感字段和版本迁移。控制台目前在局域网免登录，加入日程、本地目录、播放状态和外部服务凭据后也需要收紧访问边界。

## 提案

### 2026-08-23 基础阶段确认

本轮先建立控制台基础设施，并重做已经真实生效的能力：

- 使用 React 与 Vite 构建控制台，采用三栏配置工作台；移动端改为单列布局。
- 使用 TanStack Query 管理设备、服务状态、目录和配置的查询、轮询与变更。
- 使用 Motion 处理导航切换、预览更新和同步反馈，遵循系统的减少动态效果设置。
- 新配置文件保存主题、字体和首页设置，带 `schemaVersion` 与 `revision`；亮度继续由设备 EEPROM 保存。
- 提供目录、配置读取、带修订检查的配置修改和无副作用草稿预览接口。
- 控制台提供 `balanced`、`clock` 和 `weather` 三种首页预设，以及日期、农历和现有天气区域开关。
- 控制台显示现有设备状态、天气缓存、内存、RSSI、运行时间、帧信息和模拟手势。
- 保留旧 `/prefs` 接口，供设备内设置和兼容客户端使用。

页面列表需要等第一个真实状态页出现后再实现。天气位置、单位、刷新周期、音乐、歌词和其他数据源也留到后续阶段，本轮不加入空配置或占位入口。

### 2026-08-23 基础阶段实施结果

基础阶段的代码、自动化验证、浏览器检查和 launchd 发布已经完成：

- React/Vite 控制台取代内嵌 HTML，构建产物位于 `dist/console`，继续由 Node.js 服务提供。
- 页面使用左侧导航、中间编辑区和右侧预览；导航包含设备、首页、外观和诊断。窄屏改为单列排列。
- 界面使用中性灰、单一青绿色强调色、细分隔线和紧凑间距。常规页面没有阴影，Lucide 提供操作图标。
- TanStack Query 管理目录、设备、服务状态、配置、历史与预览。查询函数接收 `AbortSignal`；自动同步开始时取消同设备的配置查询，成功响应按修订号更新缓存，全局修订变化后清理其他设备的配置缓存。
- Motion 用于区域切换、预览加载、开关、提示和对话框，`MotionConfig` 使用 `reducedMotion="user"`。
- 配置和亮度使用独立的串行自动同步队列。控件先更新本地画面，配置静置 160 毫秒、亮度静置 120 毫秒后发送；请求期间产生的新操作会继续排队。
- 配置冲突会自动读取新版并按字段合并，本地改过的字段保留，其他字段采用服务端值。同步失败时保留当前操作并提供重试。
- 页面顶部显示同步状态、历史和发布操作。历史侧栏支持 Escape、焦点循环、背景 `inert` 和关闭后的焦点恢复。
- 预览请求只复用同一设备的占位数据。草稿预览使用独立渲染状态，失败时提供重试。实时预览后台刷新时保持已显示画面的透明度不变。
- 诊断界面显示服务配置状态、天气缓存、设备通信时间、帧号、内存、RSSI 和运行时间，并区分未上报字段与真实零值。
- 浏览器页面固定为 `100dvh`。设置区使用可换行 flex 布局，内容过长时由编辑区或历史侧栏独立滚动。发布、回退和持久化规则见[控制台实时同步与版本历史](../../implemented/architecture/2026-08-23-控制台实时同步与版本历史.md)。

### 控制台导航

控制台按任务拆成六个一级区域：

| 区域 | 内容 |
| --- | --- |
| 设备 | 在线状态、亮度、旋转、连接方式、最近帧、重启与诊断 |
| 页面 | 启用状态、手动顺序、默认页、自动出现和停留时间 |
| 首页 | 布局预设、组件槽位、天气字段、字号和实时预览 |
| 音乐 | 播放器优先级、歌词来源、缓存、翻译和页面样式 |
| 数据源 | 天气位置、日历、Home Assistant 等服务连接和健康状态 |
| 预览与诊断 | 草稿预览、模拟事件、最近错误、恢复默认和配置导出 |

设备选择保持全局可见。服务级配置在所有设备之间共享，设备级页面和布局跟随当前设备。修改自动同步并触发设备重绘，发布操作创建人工确认的版本；恢复默认需要二次确认。

### 配置分层

配置分成四类：

- 服务配置：播放器适配器、歌词来源、天气位置、缓存策略和数据源连接。
- 设备配置：主题、字体、页面列表、默认页、首页布局和安静时段。
- 设备状态：在线时间、内存、RSSI、当前页、帧诊断和设备上报的亮度。亮度修改走设备命令，不写入服务端配置文件。
- 敏感配置：访问令牌、本地目录授权和服务密钥，单独保存并在 API 中脱敏。

基础阶段的持久化文档采用版本和修订号：

```json
{
  "schemaVersion": 1,
  "revision": 17,
  "devices": {
    "desk-01": {
      "appearance": {
        "themeKey": "mono",
        "fontKey": "lxgw_wenkai_screen"
      },
      "home": {
        "layout": "balanced",
        "header": {
          "showDate": true,
          "showLunar": true
        },
        "weather": {
          "showCurrent": true,
          "showTodayRange": true,
          "showDailyOutlook": true
        }
      }
    }
  }
}
```

`schemaVersion` 处理文件格式迁移，`revision` 处理两个控制台同时修改的冲突。配置读取阶段做字段级校验，损坏文件和未知版本会把存储置为只读，并通过状态接口显示原因。

基础阶段使用 `STATE_DIR/remote-render-config.json`。每次更新同步写入权限为 `0600` 的临时文件，经原子替换成功后才发布新的内存版本和修订号。接口返回成功时，配置已经落盘；服务退出时没有待处理的异步写入。

服务配置、页面列表和安静时段等到首个真实使用场景出现时，再通过 schema 迁移加入；当前文件只保存已经生效的字段。

现有 `device-prefs.json` 在第一次加载新版配置时迁移到 `devices[id].appearance`。迁移先创建一次性备份 `device-prefs.json.migrated.bak`，备份存在后才发布新版配置文件。亮度继续由设备保存，控制台显示上报值并发送亮度命令。

设备配网页保存的新设备 ID 限制为 `1-23` 位 ASCII 字母、数字、点、下划线或连字符。Node.js 服务继续读取所有非空历史 ID，保留旧配置与已部署设备的兼容性。设备配置映射使用无原型对象，原型属性名称也能作为普通历史 ID 读取。

### 页面注册表

服务端提供页面目录，每种页面声明稳定 `kind`、显示名称、默认参数、配置字段、空状态和最低刷新间隔。设备配置中的每个页面实例包含：

```json
{
  "instanceId": "now-playing-main",
  "kind": "now_playing",
  "enabled": true,
  "manualCycle": true,
  "options": {},
  "autoShow": {
    "enabled": true,
    "priority": 60,
    "minDwellMs": 5000,
    "timeoutMs": 30000
  }
}
```

数组顺序就是手动轮换顺序。停用实例仍保留参数。默认页必须引用启用实例；删掉默认页时要求先选择新的默认页。自动页面结束后返回先前页面，先前页面已经停用时返回默认页。

首版自动触发只支持切歌、会议临近、计时结束和构建失败。控制台显示最近触发时间与原因，便于排查频繁切页。

### 首页布局

首版使用布局预设与命名槽位，允许在约束网格内调整组件。自由坐标拖放留到预设无法覆盖明确需求时再评估。

基础阶段已经提供三个预设，组件槽位阶段再评估 `minimal`：

- `clock`：大时钟、日期和一行辅助信息。
- `balanced`：时钟占上半区，下半区放两个紧凑组件。
- `weather`：时钟较小，天气当前值和预报占主要区域。
- `minimal`：只保留时钟或用户选择的一个主组件，尚未实现。

首页组件目录首批包含时钟、日期、农历、问候、当前天气、今日高低温、小时预报、未来日预报、降水、下一场日程和正在播放摘要。每个实例包含 `instanceId`、`kind`、`area`、`enabled` 和 `options`。组件目录声明最小尺寸、允许区域、最大文本行数与选项类型。

天气配置需要覆盖：

- 位置、时区、温度单位、风速单位和刷新周期；
- 当前温度、体感温度、天气描述、图标和更新时间；
- 今日高低温、降水概率、风、湿度、空气质量和日出日落；
- 小时预报数量与未来日数量；
- 紧凑、标准和预报优先三种排版。

天气组件可以全部关闭。布局校验负责越界、重叠、最小尺寸和最长文本；渲染端继续负责最终字体测量。固定 240x240 预设能让截图测试和局部刷新区域保持可控。

### 音乐与歌词配置

播放器采用有序适配器：

- `system_media`：读取 macOS 系统 Now Playing，覆盖多个播放器。
- `music_app`：通过 Music.app 自动化接口读取和控制 Apple Music。
- `spotify`：通过 Spotify Web API 获取跨设备状态，用户完成 OAuth 后启用。

控制台显示适配器是否可用、缺少的 macOS 权限、最近成功时间和脱敏错误。`auto` 模式按顺序选择第一个有活动播放状态的适配器，用户也可以固定来源。

歌词来源同样采用有序列表。本地 LRC 设置允许目录、文件命名规则和时间偏移；网络来源设置授权、语言偏好、缓存期限和容量；翻译歌词设置显示模式与行数。每次匹配保存曲目键、来源、置信度和用户修正，控制台可以搜索缓存、重新匹配或绑定本地文件。

默认不保存播放历史。缓存以曲目键索引歌词与缩放封面，并提供容量上限和清理入口。读取 API 只返回敏感项的 `configured` 状态。

### API

基础阶段已经提供以下接口：

- `GET /api/v1/catalog`：主题、字体、首页预设和亮度约束。
- `GET /api/v1/devices/:id/config`、`PATCH /api/v1/devices/:id/config`：读取和修改设备配置。
- `GET /api/v1/devices/:id/config/history`：读取当前修订、当前设备配置和最近 100 个发布版本。
- `POST /api/v1/devices/:id/config/publish`：创建配置不变的发布修订。
- `POST /api/v1/devices/:id/config/rollback`：恢复已发布配置并创建当前配置修订。
- `POST /api/v1/devices/:id/preview`：使用草稿配置渲染 PNG，不落盘，也不推进真实设备的帧序列。

配置读取返回全局 `revision` 和带双引号的 ETag。修改、发布和回退请求必须携带 `If-Match`：缺少时返回 `428`，格式错误返回 `422`，修订号过期返回 `409` 和当前修订号。控制台收到冲突后读取最新版本，按字段合并本地操作并继续同步。服务端目录是选项与约束的来源，控制台不重复维护主题、字体和首页预设常量。

服务级配置和集成状态接口随数据源阶段加入：

- `GET /api/v1/config`、`PATCH /api/v1/config`：读取和修改服务级配置。
- `GET /api/v1/integrations/status`：数据源可用性、权限和最近错误。
- `POST /api/v1/integrations/:id/test`：用户主动测试指定来源。

### 运行时更新

配置服务在保存后通知页面调度器和相关数据源：

- 页面顺序、默认页和首页布局变化时，受影响设备生成完整帧。
- 音乐切歌和天气更新时，只标记引用对应数据源的设备。
- 歌词行、时钟和计时器按页面声明的下次更新时间产生局部帧。
- 预览使用独立会话状态，不修改设备页码、输入序列和帧编号。

当前首页的天气服务是固定位置的单例。多位置配置需要改为按 weather profile 缓存，并在配置变化时重启对应轮询。当前固定的首页刷新区域在布局可配置后需要由组件边界生成，或由像素差分计算结果决定。

### 控制台代码组织

控制台使用 React 与 Vite 独立构建，产物仍由现有 Node.js 服务提供。页面状态保留在 React 内，服务端状态交给 TanStack Query；表单在打开设备时建立本地配置，自动同步响应按请求发送值合并期间产生的新操作。Motion 只负责短距离布局和透明度变化，全局设置 `reducedMotion="user"`。

三栏布局包含左侧导航、中间编辑区和右侧固定预览。首版导航只显示已经可用的设备、首页、外观和诊断；页面与数据源入口随对应功能交付后加入。

### 安全与隐私

控制台当前监听局域网且免登录。基础阶段会在写请求携带 `Origin` 时检查同源，并校验 JSON `Content-Type` 和 16 KiB 请求体上限；全部响应都设置 CSP、`frame-ancestors`、`nosniff` 与 `no-referrer`。HTTP 和串口入口继续接收非空历史设备 ID；设备配网页负责约束新 ID。

接入私人数据前完成以下工作：

- 提供仅本机访问模式或访问令牌，部署者明确选择局域网访问范围。
- 为新增配置继续限制数组数量和字符串长度。
- 本地歌词目录限定允许根目录并检查符号链接。
- 远端封面只允许 HTTP/HTTPS，设置超时、响应大小与目标地址限制。
- 令牌保存在 macOS Keychain 或专用 secrets 文件，日志过滤曲目正文、目录和令牌。

### 分阶段交付

1. 已交付 React/Vite 控制台、基础配置 schema、目录接口、字段校验、原子保存、旧偏好迁移、首页预设、草稿预览、自动同步和版本历史。
2. 页面注册表、状态页面列表、自动出现和回退调度。
3. 接入系统 Now Playing、本地 LRC 与 LRCLIB，完成音乐设置和集成状态。
4. 加入自动页面调度、安静时段和最近触发诊断。
5. 根据真实使用结果扩展日历、Home Assistant 和开发者状态页面。

## 曾考虑的替代方案

- 继续扩展 `DevicePrefs`：该结构只有主题和字体，加入服务级来源、页面实例、布局和密钥后难以定义所有权与迁移。
- 首页提供完全自由拖放和像素坐标：灵活度高，240x240 下的碰撞、文字溢出、局部刷新和截图组合数量会迅速增加。
- 继续使用无构建静态模块：初始依赖较少，配置草稿、查询缓存、冲突处理和后续复杂表单需要自行维护更多浏览器状态。用户已确认使用 React、TanStack Query 和 Motion。
- 每个页面自行读取播放器、天气和日历：会重复处理缓存、权限、错误和刷新周期，统一数据源服务更容易诊断。
- 保存每次播放和页面触发历史：有助于统计，也增加隐私和清理成本。首版只保留最近一次诊断状态。

## 风险

- 配置模型一次覆盖太多领域会拖慢首个可用版本。分阶段交付需要保持每一阶段都能独立使用。
- 当前配置写入在 Node.js 主线程同步完成。配置文件很小，写入频率也低；加入高频配置消费者前需要重新评估写入策略。
- macOS 系统媒体读取依赖私有接口时，系统升级可能造成中断。控制台要显示适配器来源和降级状态。
- Spotify、日历和家庭服务需要外部授权。认证流程、令牌刷新和撤销要分别设计。
- 局域网控制台当前缺少鉴权，新增私人数据后风险显著增加。相关安全项应进入配置扩展的第一阶段。
- 用户配置可能生成高频全屏变化。服务端需要校验组件刷新频率，并在预览中显示预计刷新范围和帧率。
- Node.js 服务接受任意非空历史设备 ID。后续修改 URL 或存储结构时，需要继续覆盖特殊名称和旧长度的兼容测试。
