# 决策记录: Web 控制台与配置模型

状态: proposed

## 问题

远端渲染服务已经有 Web 控制台，入口是 `/` 和 `/console`。当前控制台支持设备选择、PNG 预览、模拟按键、主题、字体、亮度、天气缓存与设备状态。页面由 `remote-render/src/console.ts` 中的单个 HTML 字符串提供，持久化只保存每台设备的主题和字体；亮度仍由设备 EEPROM 保存。

音乐软件、歌词来源、状态页面列表和首页布局会让配置规模明显增加。现有偏好结构无法表达服务级数据源、设备级页面实例、布局草稿、敏感字段和版本迁移。控制台目前在局域网免登录，加入日程、本地目录、播放状态和外部服务凭据后也需要收紧访问边界。

## 提案

### 控制台导航

控制台按任务拆成六个一级区域：

| 区域 | 内容 |
| --- | --- |
| 设备 | 在线状态、亮度、旋转、连接方式、最近帧、重启与诊断 |
| 页面 | 启用状态、手动顺序、默认页、自动出现和停留时间 |
| 首页 | 布局预设、组件槽位、天气字段、字号和实时预览 |
| 音乐 | 播放器优先级、歌词来源、缓存、翻译和页面样式 |
| 数据源 | 天气位置、日历、Home Assistant 等服务连接和健康状态 |
| 预览与诊断 | 草稿预览、模拟事件、最近错误、恢复默认和配置导出 |

设备选择保持全局可见。服务级配置在所有设备之间共享，设备级页面和布局跟随当前设备。修改先进入浏览器草稿，用户点击“应用”后保存并触发设备重绘；“取消”丢弃草稿，“恢复默认”需要二次确认。

### 配置分层

配置分成四类：

- 服务配置：播放器适配器、歌词来源、天气位置、缓存策略和数据源连接。
- 设备配置：主题、字体、页面列表、默认页、首页布局和安静时段。
- 设备状态：亮度、在线时间、内存、RSSI、当前页和帧诊断，只从设备上报或运行时读取。
- 敏感配置：访问令牌、本地目录授权和服务密钥，单独保存并在 API 中脱敏。

首版持久化文档采用版本和修订号：

```json
{
  "schemaVersion": 1,
  "revision": 17,
  "global": {
    "playback": {
      "enabled": true,
      "adapterOrder": ["system_media", "music_app", "spotify"]
    },
    "lyrics": {
      "sourceOrder": ["local_lrc", "cache", "lrclib"],
      "networkLookup": false
    },
    "weatherProfiles": {}
  },
  "devices": {
    "desk-01": {
      "appearance": {},
      "pages": [],
      "home": {},
      "quietHours": null
    }
  }
}
```

`schemaVersion` 处理文件格式迁移，`revision` 处理两个控制台同时修改的冲突。配置读取阶段做字段级校验，未知版本停止写入并显示诊断。保存使用临时文件和原子替换，服务退出前显式写完待保存内容。

现有 `device-prefs.json` 在第一次加载新版配置时迁移到 `devices[id].appearance`。迁移成功后保留一次备份。亮度继续由设备保存，控制台显示上报值并发送亮度命令。

### 页面注册表

服务端提供页面目录，每种页面声明稳定 `kind`、显示名称、默认参数、配置字段、空状态和最低刷新间隔。设备配置中的每个页面实例包含：

```json
{
  "instanceId": "now-playing-main",
  "kind": "now_playing",
  "enabled": true,
  "manualCycle": true,
  "options": {},
  "autoShow": {
    "enabled": true,
    "priority": 60,
    "minDwellMs": 5000,
    "timeoutMs": 30000
  }
}
```

数组顺序就是手动轮换顺序。停用实例仍保留参数。默认页必须引用启用实例；删掉默认页时要求先选择新的默认页。自动页面结束后返回先前页面，先前页面已经停用时返回默认页。

首版自动触发只支持切歌、会议临近、计时结束和构建失败。控制台显示最近触发时间与原因，便于排查频繁切页。

### 首页布局

首版使用布局预设与命名槽位，允许在约束网格内调整组件。自由坐标拖放留到预设无法覆盖明确需求时再评估。

建议提供四个预设：

- `clock`：大时钟、日期和一行辅助信息。
- `balanced`：时钟占上半区，下半区放两个紧凑组件。
- `weather`：时钟较小，天气当前值和预报占主要区域。
- `minimal`：只保留时钟或用户选择的一个主组件。

首页组件目录首批包含时钟、日期、农历、问候、当前天气、今日高低温、小时预报、未来日预报、降水、下一场日程和正在播放摘要。每个实例包含 `instanceId`、`kind`、`area`、`enabled` 和 `options`。组件目录声明最小尺寸、允许区域、最大文本行数与选项类型。

天气配置需要覆盖：

- 位置、时区、温度单位、风速单位和刷新周期；
- 当前温度、体感温度、天气描述、图标和更新时间；
- 今日高低温、降水概率、风、湿度、空气质量和日出日落；
- 小时预报数量与未来日数量；
- 紧凑、标准和预报优先三种排版。

天气组件可以全部关闭。布局校验负责越界、重叠、最小尺寸和最长文本；渲染端继续负责最终字体测量。固定 240x240 预设能让截图测试和局部刷新区域保持可控。

### 音乐与歌词配置

播放器采用有序适配器：

- `system_media`：读取 macOS 系统 Now Playing，覆盖多个播放器。
- `music_app`：通过 Music.app 自动化接口读取和控制 Apple Music。
- `spotify`：通过 Spotify Web API 获取跨设备状态，用户完成 OAuth 后启用。

控制台显示适配器是否可用、缺少的 macOS 权限、最近成功时间和脱敏错误。`auto` 模式按顺序选择第一个有活动播放状态的适配器，用户也可以固定来源。

歌词来源同样采用有序列表。本地 LRC 设置允许目录、文件命名规则和时间偏移；网络来源设置授权、语言偏好、缓存期限和容量；翻译歌词设置显示模式与行数。每次匹配保存曲目键、来源、置信度和用户修正，控制台可以搜索缓存、重新匹配或绑定本地文件。

默认不保存播放历史。缓存以曲目键索引歌词与缩放封面，并提供容量上限和清理入口。读取 API 只返回敏感项的 `configured` 状态。

### API

建议增加以下接口：

- `GET /api/v1/catalog`：播放器、歌词源、页面、组件、主题、字体和配置约束。
- `GET /api/v1/config`、`PATCH /api/v1/config`：读取和修改服务级配置。
- `GET /api/v1/devices/:id/config`、`PATCH /api/v1/devices/:id/config`：读取和修改设备配置。
- `GET /api/v1/integrations/status`：数据源可用性、权限和最近错误。
- `POST /api/v1/integrations/:id/test`：用户主动测试指定来源。
- `POST /api/v1/devices/:id/preview`：使用草稿配置渲染 PNG，不落盘，也不推进真实设备的帧序列。

配置读取返回 `revision` 或 `ETag`，修改请求携带 `If-Match`。修订号不一致时返回 `409`，控制台提示刷新并保留本地草稿。服务端目录是选项与约束的来源，控制台不再重复维护主题、字体和页面常量。

### 运行时更新

配置服务在保存后通知页面调度器和相关数据源：

- 页面顺序、默认页和首页布局变化时，受影响设备生成完整帧。
- 音乐切歌和天气更新时，只标记引用对应数据源的设备。
- 歌词行、时钟和计时器按页面声明的下次更新时间产生局部帧。
- 预览使用独立会话状态，不修改设备页码、输入序列和帧编号。

当前首页的天气服务是固定位置的单例。多位置配置需要改为按 weather profile 缓存，并在配置变化时重启对应轮询。当前固定的首页刷新区域在布局可配置后需要由组件边界生成，或由像素差分计算结果决定。

### 控制台代码组织

首期把内嵌 HTML 拆成独立的 HTML、CSS 和 JavaScript 模块，继续由 Node.js 静态提供，保持简单的开发与部署流程。页面状态、API 客户端、表单校验和预览各自成模块。组件种类和交互继续增加时，再评估独立前端构建。

### 安全与隐私

控制台当前监听局域网且免登录。接入私人数据前完成以下工作：

- 提供仅本机访问模式或访问令牌，部署者明确选择局域网访问范围。
- 校验 `Origin`、JSON `Content-Type`、请求体大小、数组数量和字符串长度。
- 增加 CSP、`frame-ancestors` 和 `nosniff` 响应头。
- 设备 ID 在 HTTP 与串口入口使用同一字符集和长度规则；控制台使用 `textContent` 创建设备选项。
- 本地歌词目录限定允许根目录并检查符号链接。
- 远端封面只允许 HTTP/HTTPS，设置超时、响应大小与目标地址限制。
- 令牌保存在 macOS Keychain 或专用 secrets 文件，日志过滤曲目正文、目录和令牌。

### 分阶段交付

1. 配置 schema、目录接口、字段校验、原子保存和旧偏好迁移。
2. 拆分控制台静态资源，完成设备、页面和首页预设编辑，以及无副作用草稿预览。
3. 接入系统 Now Playing、本地 LRC 与 LRCLIB，完成音乐设置和集成状态。
4. 加入自动页面调度、安静时段和最近触发诊断。
5. 根据真实使用结果扩展日历、Home Assistant 和开发者状态页面。

## 曾考虑的替代方案

- 继续扩展 `DevicePrefs`：该结构只有主题和字体，加入服务级来源、页面实例、布局和密钥后难以定义所有权与迁移。
- 首页提供完全自由拖放和像素坐标：灵活度高，240x240 下的碰撞、文字溢出、局部刷新和截图组合数量会迅速增加。
- 首轮引入完整 React 控制台构建：表单规模最终可能需要组件框架，当前先拆成静态模块可以减少构建与发布改动。
- 每个页面自行读取播放器、天气和日历：会重复处理缓存、权限、错误和刷新周期，统一数据源服务更容易诊断。
- 保存每次播放和页面触发历史：有助于统计，也增加隐私和清理成本。首版只保留最近一次诊断状态。

## 验收标准

- 配置 schema 明确服务配置、设备配置、运行状态和敏感配置的归属。
- 旧主题与字体偏好可以迁移，损坏文件和未知版本有明确诊断，保存过程经过原子写入和退出写完测试。
- 控制台可以启停与排序页面，设置默认页，并配置首页预设和天气字段。
- 草稿预览不改变真实设备的页面状态、输入序列或帧编号。
- 两个控制台同时编辑时可以检测修订冲突并保留未应用草稿。
- 页面调度覆盖停用跳过、默认页约束、自动出现优先级、最短停留、超时和回退。
- API 覆盖字段校验、设备 ID、认证或本机限制、Origin、请求体上限和敏感字段脱敏。
- 每个首页预设在 240x240 下有极端文本截图，文本不越界，配置变更后的差分帧可以还原正确画面。
- 播放器与歌词来源有适配器契约测试，覆盖权限缺失、超时、限流、缓存命中、缺词和错误匹配修正。

## 风险

- 配置模型一次覆盖太多领域会拖慢首个可用版本。分阶段交付需要保持每一阶段都能独立使用。
- macOS 系统媒体读取依赖私有接口时，系统升级可能造成中断。控制台要显示适配器来源和降级状态。
- Spotify、日历和家庭服务需要外部授权。认证流程、令牌刷新和撤销要分别设计。
- 局域网控制台当前缺少鉴权，新增私人数据后风险显著增加。相关安全项应进入配置扩展的第一阶段。
- 用户配置可能生成高频全屏变化。服务端需要校验组件刷新频率，并在预览中显示预计刷新范围和帧率。
- `device-prefs.json` 当前只做顶层类型检查。迁移前需要对旧数据逐字段读取，保留备份，失败时继续使用现有配置并停止写入新版文件。
